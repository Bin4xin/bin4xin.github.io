# 数据安全与AI安全理论赛知识点汇编

> 本文档汇总了数据安全与AI安全理论赛的全部题目与答案，按题型分类整理，便于复习与查阅。


## 一、判断题（1分/题）

| 题号 | 题目关键词 | 答案 | 简要解析 |
|------|-----------|------|----------|
| 1 | 境外法律要求更高不需重评 | **否** | 仍需依法重新评估，不能免除我国法律规定的评估义务 |
| 2 | AI伦理审查为形式化流程 | **否** | 对系统开发有实质性影响，非形式化流程 |
| 3 | PEFT不属于微调 | **否** | 参数高效微调（Parameter-Efficient Fine-Tuning）**是微调的子集**，只调整部分参数（如 LoRA、Adapter），并非"不属于微调" |
| 4 | 数据质量验证只关注准确性 | **否** | 还需关注完整性、一致性、时效性等多维度 |
| 5 | 展示重要数据需脱敏 | **是** | 脱敏是保护敏感信息的基本措施 |
| 6（网安法） | 网安法要求保护个人信息 | **是** | 《网络安全法》明确规定了该义务 |
| 7（人工在环） | 所有任务都应人工在环 | **否** | 非所有任务适合，部分自动化流程可独立完成 |
| 8（数据生命周期） | 数据创建阶段考虑生命周期 | **是** | 从创建开始规划全生命周期管理 |
| 9（Oracle哈希） | 相同用户名密码跨库哈希相同 | **是** | Oracle早期密码哈希未加全局盐，相同输入产生相同哈希 |
| 10（3DES） | 3DES是DES改进 | **是** | 三重加密（加密→解密→加密）提升安全性 |
| 11（数据结构破坏） | 数据结构破坏不属于数据污染 | **否** | 属于数据污染攻击的常见手段 |
| 12（Prompt注入） | Prompt注入仅影响文本模型 | **否** | 多模态模型（图像、音频）同样可能受影响 |
| 13（数据主体权利） | 数据主体权利绝对 | **否** | 存在例外情形（如国家安全、公共利益），非无条件满足 |
| 14（数据源伪造） | 伪造查询结果=修改原始数据 | **否** | 通常指在查询返回层面篡改结果，不涉及底层数据修改 |
| 15（风险评估） | 风险评估目标为识别量化风险 | **是** | 风险评估的核心目的 |
| 16（灰度数据共享） | 灰度数据可随意对外共享 | **否** | 仍需遵守保密协议和安全规范 |
| 17（邮件加密） | 邮件发送应加密防错发 | **是** | 加密防截获，防错发是基本安全要求 |
| 18（数据漂移） | 数据漂移仅训练阶段出现 | **否** | 部署后也会出现（数据分布变化），需持续监控 |
| 19（保留期限） | 保留期限由企业自行设定 | **否** | 受法律法规约束，不能仅依存储成本决定 |
| 20（持续学习） | 持续学习系统无需重做安全评估 | **否** | 更新模型可能引入新风险，需重新评估 |

## 三、不定项选择题（2分/题）

| 题号 | 题目 | 答案 | 解析 |
|------|------|------|------|
| 1（输入变换） | 特征压缩提升鲁棒性 | 滤波操作、像素值量化 | 特征压缩通过降低输入空间维度，减少对抗扰动的影响，**不是**增加模型复杂度 |
| 2（白盒攻击） | 可利用的信息 | 模型结构、模型参数、损失函数梯度 | 白盒攻击拥有模型全部信息，**比黑盒攻击更强大**；训练数据不属于白盒攻击直接可利用的信息 |
| 3（系统加固） | 主要目的 | 提高攻击难度、减小自身脆弱性 | 系统加固通过关闭不必要服务、修补漏洞、强化配置来**增加攻击成本** |
| 4（安全AI生命周期） | 应融入安全考虑的阶段 | 数据准备、模型设计与训练、部署监控、废弃（**全选**） | 安全必须贯穿 AI 生命周期**所有阶段**，不能只在部署后才考虑 |
| 5（模型反演） | 可能重建的内容 | 训练数据特征、类原型 | 模型反演攻击通过模型输出推断训练数据的统计特征，**不能**精确还原原始数据 |
| 6（联邦学习） | 核心技术手段 | 加密技术 | 联邦学习通过同态加密/安全多方计算保护梯度传输，**原始数据不离开本地** |
| 7（系统安全漏洞） | 属于漏洞的问题 | 产品缺少安全功能、产品有Bugs | 安全漏洞包括设计缺陷（缺少安全功能）和实现缺陷（Bugs），**不包括**配置错误（那是运维问题） |
| 8（GDPR跨境传输） | 合法传输机制 | 充分性认定、标准合同条款、约束性企业规则 | GDPR 第 44-49 条规定的三大合法传输机制；**不包括**用户同意（需满足额外条件） |
| 9（后门触发器） | 关键设计因素 | 颜色、模式、位置、大小（**全选**） | 后门触发器的设计需要考虑所有视觉/模式特征，确保隐蔽性和可触发性 |
| 10（Hash函数） | 基本特性 | 抗碰撞性、输入长度任意、计算高效 | Hash 函数核心特性三要素：**抗碰撞 + 输入任意 + 计算高效**。输出长度固定是事实描述但不属于"安全特性"范畴 |
| 11（AI客服幻觉） | 降低风险策略 | 用户反馈、置信度阈值、人工复核 | 三层防御：**置信度过滤（自动）→ 人工复核（半自动）→ 用户反馈（事后纠正）** |
| 12（大模型泄露来源） | 可能来源 | 训练数据记忆、API越权、模型逆向工程 | 大模型数据泄露三大路径：**记忆效应（模型记住了训练数据）+ API 越权访问 + 模型逆向提取** |
| 13（物理隔离失效） | 导致失效的情况 | 网络非法外联 | 物理隔离失效的**最常见原因**是内部人员违规连接外部网络（如私接 WiFi、使用移动热点） |
| 14（SET成员） | 不属于SET成员 | 电子钱包 | SET（安全电子交易）成员：持卡人、商户、发卡行、收单行、支付网关、CA。**电子钱包是客户端工具，不是协议参与方** |
| 15（模型评估维度） | 核心维度 | 鲁棒性、隐私保护、抗攻击性、合规性（**全选**） | 模型安全评估必须多维度覆盖，**缺一不可** |
| 16（越狱攻击） | 核心目标 | 绕过安全防护机制 | 越狱攻击（Jailbreak）通过精心构造的 Prompt 绕过模型的安全对齐，**不是**获取训练数据 |
| 17（数据备份） | 核心目的 | 防止丢失、恢复误删数据 | 备份是**恢复性控制**，不是预防性控制；它不能防止数据丢失，只能在丢失后恢复 |
| 18（防止模型篡改/窃取） | 有效措施 | 限制访问、加密权重、数字签名 | 三重保护：**访问控制（防未授权访问）+ 加密（防窃取）+ 签名（防篡改）** |
| 19（ICF防火墙） | 可实现功能 | 禁止端口扫描、检查地址、网络层检查（不防病毒） | 状态防火墙工作在**网络层和传输层**，不具备应用层内容检测能力，**不能防病毒** |
| 20（公钥密码） | 基本思想 | 加密公钥公开，解密私钥保密 | 公钥密码核心：**公钥加密、私钥解密**；安全性基于数学难题（如大数分解、离散对数），由公钥推私钥**计算不可行** |

### 4.1 数据安全核心概念对比

| 概念 | 定义 | 关键区别 | 典型考法 |
|------|------|----------|----------|
| **脱敏** | 对敏感信息进行变形处理（掩码、替换、泛化） | 隐藏信息，**可逆**（有规则即可还原） | "最适合实施脱敏的阶段" → 使用和共享 |
| **加密** | 用密钥将明文转为密文 | 保护信息，**不可逆**（无密钥无法还原） | "邮件发送应加密防错发" → 是 |
| **匿名化** | 彻底去除个人标识符，无法重新关联 | **不可逆**且不可重新识别 | 与脱敏的根本区别：是否可重新识别 |
| **假名化** | 用假标识符替代真实标识符 | **可逆**（持有映射表可还原） | GDPR 下假名化仍是个人数据 |

{% include common-index/index-preset.html level="info" msg="<strong>脱敏 vs 加密</strong>：脱敏是「让你看不懂」，加密是「让你拿不到」。脱敏后数据仍可展示使用，加密后必须解密才能用。" %}

### 4.2 访问控制模型对比

| 模型 | 全称 | 权限由谁决定 | 严格程度 | 典型场景 |
|------|------|-------------|----------|----------|
| **DAC** | 自主访问控制 | 数据所有者 | ⭐⭐ | 文件系统权限（Linux chmod） |
| **MAC** | 强制访问控制 | 系统/管理员（安全标签） | ⭐⭐⭐⭐⭐ | 军事系统、涉密系统 |
| **RBAC** | 基于角色的访问控制 | 角色分配 | ⭐⭐⭐ | 企业 OA、ERP 系统 |
| **ABAC** | 基于属性的访问控制 | 属性策略引擎 | ⭐⭐⭐⭐ | 云环境、微服务 |

{% include common-index/index-preset.html level="warn" msg="考题问「最严格有效的访问控制」→ 答案永远是 <strong>MAC（强制访问控制）</strong>。MAC 由系统强制执行安全标签，用户无法自行修改，是四级以上的安全要求。" %}

### 4.3 AI攻击类型对比

| 攻击类型 | 作用阶段 | 核心手段 | 目标 |
|----------|----------|----------|------|
| **投毒攻击** | 训练阶段 | 篡改训练数据 | 注入后门 / 降低精度 |
| **对抗攻击** | 推理阶段 | 构造对抗样本 | 误导模型输出 |
| **模型反演** | 推理阶段 | 分析模型输出 | 重建训练数据特征 |
| **模型窃取** | 推理阶段 | 查询 API 复制模型 | 获取模型知识产权 |
| **Prompt注入** | 推理阶段 | 构造恶意 Prompt | 绕过安全对齐 |
| **越狱攻击** | 推理阶段 | 精心设计 Prompt | 绕过安全防护机制 |

{% include common-index/index-preset.html level="info" msg="<strong>投毒 vs 对抗</strong>：投毒在<strong>训练阶段</strong>污染数据，对抗在<strong>推理阶段</strong>欺骗模型。一个是「下毒」，一个是「伪装」。" %}

{% include common-index/index-preset.html level="warn" msg="<strong>Prompt注入 vs 越狱</strong>：Prompt注入是让模型执行<strong>非预期指令</strong>（如泄露系统提示词），越狱是让模型<strong>突破安全限制</strong>（如生成违规内容）。注入侧重「劫持」，越狱侧重「突破」。" %}

### 4.4 密码学概念对比

| 概念 | 密钥 | 方向 | 典型算法 | 用途 |
|------|------|------|----------|------|
| **对称加密** | 加解密同一密钥 | 双向 | AES、3DES | 大量数据加密 |
| **非对称加密** | 公钥加密、私钥解密 | 单向 | RSA、ECC | 密钥交换、数字签名 |
| **Hash函数** | 无密钥 | 不可逆 | SHA-256、MD5 | 完整性校验、数字签名 |
| **同态加密** | 公私钥对 | 密文计算 | CKKS、BGV | 云端隐私计算 |

{% include common-index/index-preset.html level="info" msg="Hash函数三大特性口诀：<strong>「抗碰撞、任意入、算得快」</strong>。输出长度固定是事实但不属于安全特性；<strong>可逆计算绝对不选</strong>——Hash 的安全性就建立在不可逆之上。" %}

### 4.5 数据生命周期阶段与安全措施

| 阶段 | 关键安全措施 | 易混淆点 |
|------|-------------|----------|
| **创建** | 全生命周期规划、分类分级 | 不是"创建后才考虑安全" |
| **存储** | 加密、访问控制、备份 | 脱敏主要不在存储阶段 |
| **使用** | 脱敏、审计、最小权限 | **最适合脱敏的阶段** |
| **共享** | 脱敏、传输加密、合同约束 | **最适合脱敏的阶段** |
| **分发** | 责任不随数据转移 | 分发≠共享，分发后仍有责任 |
| **销毁** | 独立人员确认记录 | 销毁≠删除，需有审计记录 |

{% include common-index/index-preset.html level="success" msg="数据生命周期考点口诀：<strong>「创建规划、存储加密、使用脱敏、共享脱敏、分发担责、销毁审计」</strong>。其中「使用和共享阶段最适合脱敏」是高频考点。" %}

### 4.6 网络安全控制类型对比

| 控制类型 | 作用时机 | 典型手段 | 考题关键词 |
|----------|----------|----------|-----------|
| **预防性** | 事件发生前 | 防火墙、访问控制、加密 | "阻止"、"防止" |
| **检测性** | 事件发生时 | 审计跟踪、入侵检测、日志 | "发现"、"检测"、"记录" |
| **纠正性** | 事件发生后 | 备份恢复、补丁更新 | "恢复"、"修复" |
| **补偿性** | 主控失效时 | 冗余系统、应急预案 | "替代"、"补偿" |

{% include common-index/index-preset.html level="warn" msg="第 29 题「属于检测性控制」→ <strong>审计跟踪</strong>。防火墙是预防性，备份是纠正性。记住：<strong>审计 = 检测</strong>，它不阻止事件，只记录和发现事件。" %}

### 4.7 法律法规要点速记

| 法规 | 核心考点 | 易错点 |
|------|----------|--------|
| **《网络安全法》** | 保护个人信息义务、网络安全等级保护 | 不等于《数据安全法》 |
| **《数据安全法》** | 数据定义（任何记录方式）、数据分类分级 | 数据范围比"电子数据"更广 |
| **《个人信息保护法》** | 个人信息处理规则、跨境传输 | 与网安法的适用范围区分 |
| **GDPR** | 跨境传输三大机制（充分性/SCC/BCR） | 用户同意不是独立传输机制 |

{% include common-index/index-preset.html level="info" msg="三法区分口诀：<strong>「网安管安全、数安管数据、个保管个人」</strong>。GDPR 跨境传输记住三个关键词：<strong>充分性认定、标准合同条款（SCC）、约束性企业规则（BCR）</strong>。" %}
