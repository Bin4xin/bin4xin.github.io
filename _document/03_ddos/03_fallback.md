## 场景 4 — 阶段三：业务保底运行

### 业务优先级分级

| 等级 | 业务 | 保底策略 | SLA |
|------|------|----------|-----|
| P0 | 支付 / 交易 | 多活切换 + 降级 | 99.9% |
| P0 | 用户认证 | CDN 缓存 + 降级 | 99.9% |
| P1 | 核心 API | 限流 + 排队 | 99% |
| P1 | 首页 / 商品 | 静态缓存兜底 | 99% |
| P2 | 后台管理 | 临时关闭 | 尽力而为 |
| P2 | 数据分析 | 暂停服务 | 可延迟 |

> 核心原则：保 P0 · 降 P1 · 放 P2

### 业务降级策略

| 策略 | 说明 |
|------|------|
| 静态化兜底 | 动态页面降级为静态缓存版本，首页 / 商品页 CDN 缓存命中 |
| 限流排队 | API 限速 + 用户排队机制，超过阈值返回"系统繁忙" |
| 功能精简 | 关闭非核心功能：搜索 / 推荐 / 评论暂停服务 |
| 多活切换 | 将流量切换到未受攻击的可用区 |
| 渠道切换 | Web 不可用时引导至 App，App 不可用时引导至小程序 |

### 攻击期间 SLA 监控

| 指标 | 目标 |
|------|------|
| 支付成功率 | > 99% |
| API 可用性 | > 95% |
| 页面加载时间 | < 5s |
| 错误率 (5xx) | < 5% |
| 清洗率 | > 99.5% |
