## 技战法概述

Linux 服务器是企业 IT 基础设施中最广泛使用的操作系统之一，承载着 Web 应用、数据库、中间件等核心业务系统。然而，在实际运维过程中，Linux 服务器的安全配置往往存在诸多问题：默认配置未根据安全需求进行加固、不必要的服务和端口处于开放状态、权限设置过于宽松、审计日志不完整等。这些配置缺陷可能被攻击者利用，作为入侵和横向移动的跳板。

安全基线（Security Baseline）是指针对特定系统或平台制定的最低安全配置标准，确保系统在安全层面满足基本要求。最小权限原则（Principle of Least Privilege）是安全基线设计的核心思想，即只授予用户、进程和系统完成其功能所必需的最小权限，不多一分。

### 三阶段技战法

| 阶段 | 名称 | 关键目标 |
|------|------|----------|
| 阶段一 | 安全基线制定 | 根据行业最佳实践和企业实际需求，制定 Linux 服务器的安全基线标准 |
| 阶段二 | 基线配置实施 | 将安全基线应用于 Linux 服务器，完成安全加固配置 |
| 阶段三 | 自动化核查与持续合规 | 开发自动化核查脚本，定期检查服务器安全配置是否符合基线要求 |

### 常见配置问题分布

| 问题类型 | 占比 | 说明 |
|----------|------|------|
| 权限设置过宽 | 22% | 关键文件权限过松，sudo 配置不合理 |
| 不必要服务开放 | 18% | 默认安装的服务未关闭，增加攻击面 |
| 弱口令/空口令 | 15% | 用户使用弱密码或无密码 |
| SSH 配置不安全 | 12% | 允许 root 远程登录、未限制来源 |
| 审计日志不完整 | 12% | 关键操作未记录，日志保留期不足 |
| 补丁更新滞后 | 10% | 内核/组件版本过旧，已知漏洞未修复 |
| 内核参数不安全 | 6% | 网络协议栈参数未加固 |
| 文件系统配置 | 5% | 临时目录无 nosuid/nodev、未启用磁盘配额 |
