## 场景 3 — 阶段三：修补跟踪与闭环管理

### 修补工作流

| 步骤 | 名称 | 说明 |
|------|------|------|
| 1 | 工单自动派发 | 量化评估结果自动生成工单，按等级分配给对应责任人，P0→电话通知 P1→IM P2→邮件 |
| 2 | 修补方案确认 | 补丁修补 / 配置加固 / 补偿控制，影响评估 + 回退方案准备，P0 需安全 + 运维 + 开发三方确认 |
| 3 | 测试验证 | 测试环境先行修补验证，功能回归 + 性能测试，确认无兼容性问题 |
| 4 | 生产环境修补 | 灰度发布 → 逐步推广，P0 紧急修补可变更流程简化，全程记录操作日志 |
| 5 | 复扫验证关闭 | 修补后自动触发复扫，确认漏洞已修复后关闭工单，未修复则退回重新处理 |

### 修补与缓解策略

| 策略 | 说明 |
|------|------|
| 补丁修补（首选） | 官方补丁/升级版本/热修复，影响最小化 + 测试验证后部署 |
| 配置加固 | 关闭漏洞利用所需的配置项，如禁用不安全的功能/接口 |
| 补偿控制（临时） | WAF 规则 / IPS 签名 / 网络 ACL，购买修补时间窗口，不替代修补 |
| 组件替换 | 替换存在漏洞的第三方组件，升级到安全版本/替代方案 |
| 服务下线 | 无法修补且风险不可接受时，临时/永久下线受影响服务 |

### 例外管理与升级

| 机制 | 说明 |
|------|------|
| 例外审批流程 | 无法按时修补需提交例外申请，说明原因 + 补偿措施 + 风险评估，P0 需 CISO 审批 |
| SLA 超期升级 | 超期 50% → 系统自动提醒，超期 80% → 安全团队介入，超期 100% → 管理层通报 |
| 定期通报机制 | 周报：修补进度/超期风险，月报：漏洞趋势/SLA 达成率，季报：漏洞管理成熟度评估 |
| 持续优化闭环 | 月度 Top10 漏洞根因分析，修补效率持续改进，自动化覆盖率提升 |
