## 场景 4 — 阶段三：清理实施与持续治理

### 清理实施方案

| 阶段 | 动作 | 说明 |
|------|------|------|
| 1. 审批确认 | 清理方案评审 | 安全团队 + 网络团队 + 业务方联合评审 |
| 2. 备份 | 策略全量备份 | 清理前完整备份所有策略规则，含版本号和时间戳 |
| 3. 预执行 | 影响分析 | 模拟清理后的策略效果，验证无业务影响 |
| 4. 分批执行 | 灰度清理 | 低风险规则先行清理，观察 1-2 周后再清理高风险规则 |
| 5. 验证 | 业务验证 | 清理后验证所有关键业务连通性 |
| 6. 存档 | 清理报告 | 记录清理清单、变更内容、验证结果 |

### 清理优先级

| 优先级 | 类型 | 数量 | 说明 |
|--------|------|------|------|
| P0 | 已禁用规则 | 267 | 确认无影响后直接删除 |
| P1 | 阴影规则 | 345 | 永不执行，确认后删除 |
| P2 | 冗余规则 | 690 | 被覆盖的规则，确认后删除 |
| P3 | 过期规则 | 414 | 90天+未命中，先禁用观察再删除 |
| P4 | 过宽规则 | 495 | 需业务方确认后精确化处理 |

| 指标 | 清理前 | 清理后 | 改善 |
|------|--------|--------|------|
| 总规则数 | 3,449 | 1,920 | -44% |

### 持续治理机制

| 机制 | 说明 |
|------|------|
| 规则生命周期管理 | 每条规则必须标注责任人/业务用途/有效期，到期自动提醒续期或清理 |
| 新规则审批流程 | 新增规则需业务申请 → 安全评审 → 精确化配置 → 生效，禁止使用 any 字段 |
| 定期审计 | 月度：未命中规则扫描，季度：全面策略审计，年度：策略架构评审 |
| 自动化检测 | 每日自动扫描新增冗余/阴影/过宽规则，实时告警并通知责任人 |
| 指标看板 | 持续监控规则健康度指标，管理层月度通报 |

### 规则生命周期

申请(责任人/业务用途/有效期) → 审批(安全+网络评审) → 部署(精确化配置)
→ 运行(命中监控/定期审计) → 到期(续期/清理) → 下线(备份删除)


### 关键度量指标

| 指标 | 目标 |
|------|------|
| 规则健康评分 | ≥ 80/100 |
| 30天未命中占比 | < 10% |
| 使用 any 占比 | < 5% |
| 有描述规则占比 | ≥ 90% |
| 有责任人规则占比 | ≥ 95% |
| 清理响应时间 | < 5 个工作日 |
