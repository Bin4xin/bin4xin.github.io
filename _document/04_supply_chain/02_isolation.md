## 场景 3 — 阶段二：紧急隔离与业务切换

### 紧急隔离措施

1. **切断供应商通道**：禁用供应商 VPN 账户，撤销堡垒机访问权限，阻断供应商管理端口
2. **阻断 C2 通信**：防火墙封锁已知 C2 IP / 域名，DNS Sinkhole 劫持 C2 域名
3. **生产网段隔离**：受感染网段 ACL 严格限制，仅允许业务必要流量
4. **凭证全面轮换**：所有管理员密码 / API Key / 证书，数据库凭证 / 云访问密钥
5. **日志保全**：锁定所有系统日志，备份网络流量 / 操作审计

### 业务切换方案

| 方案 | 说明 | 适用场景 |
|------|------|----------|
| A. 灾备环境接管 | 切换到异地灾备中心 | 灾备建设完善的企业 |
| B. 回滚到安全版本 | 回退到最后已知安全的版本 / 镜像 | 版本管理规范的企业 |
| C. 全新环境重建 | 使用干净源码重新构建部署 | 最彻底但耗时最长 |
| D. 替代供应商 / 组件 | 临时切换到替代供应商 | 有备选方案的企业 |

### 安全版本构建要点

1. **干净源码验证**：从 Git 仓库验证代码完整性，比对 commit 哈希与签名
2. **安全依赖锁定**：使用 lockfile 锁定安全版本，替换受影响组件到安全版本
3. **可信构建环境**：在隔离的 CI/CD 环境中构建，构建服务器重置 + 加固
4. **镜像安全扫描**：构建后全量漏洞 + 后门扫描，哈希签名并记录到 SBOM
5. **灰度部署验证**：少量节点先部署验证，确认无异常后全量切换

### 切换验证清单

- [ ] 安全版本已通过完整性校验
- [ ] 构建环境已隔离加固
- [ ] 数据完整性确认
- [ ] 凭证已全面轮换
- [ ] C2 通信已阻断

> 业务切换完成 → 进入阶段三：全面排查清除
